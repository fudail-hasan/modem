# Linux Modem Server Emulator 🚀

This guide explains how to configure a virtual serial loopback device on Linux, interact with the server application, and run the compilation pipeline.

---

## 🛠️ Step 1: Configure the Virtual Modem (PTY Loopback)

Since physical modems are rarely connected to development machines, you can create a pair of connected virtual serial ports—called **Pseudo-Terminals (PTYs)**—using the `socat` tool.

1. Open a new terminal window.
2. Install `socat` if it isn't already installed:
   ```bash
   sudo apt install socat
   ```
3. Create the loopback bridge:
   ```bash
   socat -d -d pty,raw,echo=0 pty,raw,echo=0
   ```
4. The output will show two virtual endpoints allocated by the Linux kernel, for example:
   ```text
   2026/09/03 03:03:15 socat[12345] N PTY is /dev/pts/2
   2026/09/03 03:03:15 socat[12345] N PTY is /dev/pts/3
   ```
   * **`/dev/pts/2`** will act as the modem's hardware port (connected to our C++ server).
   * **`/dev/pts/3`** will act as the client machine link (where you type your commands).

*(Note: Keep this terminal window open! Closing it destroys the virtual connections.)*

---

## 📦 Step 2: Build and Run the Code

The project uses CMake to cross-compile binary packages natively under Linux.

1. Ensure you have the standard compiler collection installed:
   ```bash
   sudo apt update
   sudo apt install build-essential cmake
   ```
2. Open **`main.cpp`** and make sure the `ttyPort` variable matches the first port generated by `socat` (e.g., `"/dev/pts/2"`).
3. Grant execution rights to the helper script and execute it to build and launch the application:
   ```bash
   chmod +x build_run.sh
   ./build_run.sh
   ```

The program will load your `config.csv` dictionary files and enter a continuous blocking read loop, waiting for client AT instructions.

---

## 💬 Step 3: Communicate with the Server

With the server running in its own terminal, open a **third terminal window** to simulate standard client serial interactivity over the second virtual endpoint (e.g., `/dev/pts/3`).

### Option A: Using Simple Terminal Redirection
You can push text directly down the pipe using `echo` and inspect output buffers using `cat`:

1. Start listening to responses in your client terminal:
   ```bash
   cat /dev/pts/3
   ```
2. Open another terminal or split-view pane, and send AT commands down the client pipeline:
   ```bash
   echo "AT" > /dev/pts/3
   echo "ATI" > /dev/pts/3
   echo "AT2E" > /dev/pts/3
   ```

### Option B: Using a Serial Terminal Emulator (`minicom`)
For an interactive workspace mimicking a real hardware terminal application link:

1. Install minicom:
   ```bash
   sudo apt install minicom
   ```
2. Connect to the client virtual serial link port:
   ```bash
   minicom -D /dev/pts/3 -b 115200
   ```
3. Type commands like `AT` or `ATI` directly into the panel view and press **Enter** to see the custom Trie matcher answers return instantly over the line link.
